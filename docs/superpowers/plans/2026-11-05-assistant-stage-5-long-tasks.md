# Помощник 2.0, этап 5 «Длинные задачи» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Длинные задачи и длинные чаты не переполняют окно контекста локальной модели, а прерванная задача продолжается одной кнопкой с того места, где остановилась.

**Architecture:** Без дополнительных вызовов модели: детерминированное сжатие. Внутри одного ответа агента перед каждым ходом (`prepareMessages`) оценивается размер истории (символы / 4) и при приближении к окну контекста скрывается больше старых результатов. Между ответами в историю для модели идут все сообщения пользователя полностью, а старые ответы помощника укорачиваются; ответы агента несут краткий список своих шагов, чтобы модель знала, что уже сделано. В панели у прерванного или остановленного ответа агента — кнопка «Продолжить».

**Tech Stack:** как этапы 1–4.

**Spec:** `docs/superpowers/specs/2026-11-04-ai-assistant-design.md` — «История» (сжатие, сообщения пользователя полностью, «прервана» после перезапуска и продолжение новым сообщением), «Порядок работ» п. 5.

## Global Constraints

- Оценка размера — символы / 4 (токен ≈ 4 символа), как у бюджета описания страницы; окно контекста — `modelContext` (этап 2).
- Внутри ответа: порог 70 % окна. Уровни: обычный — последние 3 результата читающих инструментов; при превышении — последний 1; при превышении и после этого — квитанции действий старше последних 10 сокращаются до первой строки.
- Между ответами: бюджет истории — 50 % окна. Сообщения пользователя никогда не сокращаются. Ответы помощника сокращаются от старых к новым до 300 символов с пометкой «…[ответ сокращён]», затем, если всё ещё много, — до одной строки; последний ответ не сокращается.
- Ответ агента в истории для модели дополняется строкой «Шаги: snapshot · click «Удалить» · done (выполнено частично)» (до 20 шагов, с итогом и статусом `прервано`/`остановлено`, если так).
- Кнопка «Продолжить» — у последнего ответа чата, если он в режиме «Агент» и со статусом `interrupted` или `stopped`; отправляет «Продолжи задачу с того места, где остановился. Сначала посмотри, что сейчас на странице.» в том же чате.

## Review Focus

- Чат из 200 сообщений — запрос к модели укладывается в бюджет, все сообщения пользователя на месте. → тест `история укладывается в бюджет` (Task 2).
- Агент делает 60 шагов с крупными страницами — перед каждым ходом история ≤ 70 % окна. → тест `fitToContext держит порог` (Task 1).
- Worker остановлен посреди задачи агента — после открытия панели ответ «прервано» со своими шагами, «Продолжить» запускает агента, модель видит в истории, что уже было сделано. → e2e `resume` (Task 3).
- Пользователь нажал «Стоп», потом «Продолжить» — продолжает в тех же вкладках (память вкладок чата). → тест `продолжение берёт вкладки чата` (Task 3).
- Модель без вызова инструментов в длинном чате — история не обрезает последний ответ и не теряет вопрос пользователя. → тест `последний ответ и все вопросы целы` (Task 2).

### Task 1: Удержание истории внутри ответа агента

**Files:**
- Modify: `app/src/agent/elision.ts`
- Test: `app/tests/elision.test.ts`

**Interfaces:**
- Produces: `estimateTokens(messages: unknown[]): number` (сумма длин текстовых частей и строковых `output.value` / 4; изображения — 1000 токенов каждое); `fitToContext<T>(messages: T[], contextTokens: number): T[]` — уровни из Global Constraints до тех пор, пока `estimateTokens ≤ 0.7 × contextTokens` или уровни не кончились.
- В `ChatRunner` агентный `prepareMessages` = `m => screenshots.inject(fitToContext(m, context))`, где `context` — `modelContext` (зависимость `contextTokens?: (settings) => Promise<number>`, по умолчанию 8192).
- [ ] **Step 1: Тесты:** `estimateTokens` на известных сообщениях; `fitToContext держит порог` (60 результатов `snapshot` по 4000 символов при окне 32768 → результат ≤ 0.7 × 32768, последний `snapshot` цел, сообщение пользователя целое); маленькая история не меняется (тот же объект).
- [ ] **Step 2–4:** FAIL → реализация → PASS. **Step 5: Commit** `"Удержание истории агента в окне контекста"`.
